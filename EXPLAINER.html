🛑 Parada Determinística de Paginação por URL Conhecida

2026-08-05 · branch main · commit bde5def

Diagnóstico

A parada de paginação added === 0 depende da tabela frontier para reconhecer URLs já vistas. Se a frontier for limpa (purge/reset), TODOS os links voltam a ser "novos" e o crawler anda o arquivo inteiro novamente.

A parada por data (below > 0) depende de seletores de data que não existem para fontes Cooperpress.

Solução: verificar se as URLs dos links da página de listagem já existem nas tabelas de conteúdo capturado (articles, pages, frontier done, articles.issue_url) — determinístico, zero LLM.

Mudanças

src/db.jsNovo statement isUrlKnown: consulta URL em articles.url, pages.url, frontier.url (done) e articles.issue_url
src/crawl.jscrawlArchive + fallback item-a-item: conta links conhecidos antes de enfileirar; se 100% conhecidos → break imediato; se ≥50% → log de território conhecido
Cobertura

  • Fontes listing (llmnews.ai): URLs de artigo reconhecidas via articles.url — ~82% de match
  • Parada 100%: quando TODOS os links da página são conhecidos → break imediato
